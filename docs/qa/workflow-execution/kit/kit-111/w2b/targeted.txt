The new block on the start commit errors at its second send ("native reference roots contain a live payload",
test-first.txt) and passes after (6/6). Its last expectation checks that the hit leaves the product's root
(snapshot$product_dependencies) identical to the root the first, computed run published.

Fix as made (R/utils_workflow_omics_declarations.R, computeWorkflowOmicsOperationAction): a hit roots the source, the
dependencies and the saved references its value names (collectWorkflowNativeReferences(run$value)). A value holding a
live payload (a product-only declaration's science, e.g. the pearson pairs data frame) contributes none, so such a hit
is rooted with the source and the dependencies only. Every hit that worked before (a state-producing value, which is
only references and atomics) is rooted exactly as before. Because a hit overwrites the product's
product_dependencies entry, dropping the value outright would remove references that were rooted only through that
entry, such as the RUV optimisation product. The session export collects its reachable set from the snapshot.
