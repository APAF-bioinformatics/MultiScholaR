## What was built

1. **Q-value filter as a declaration** (`R/utils_workflow_dia_state.R`): `runDIAReferenceQvalue` (GUI entry, contract unchanged) is now a wrapper over `computeDIAReferenceQvalue(manager, reference, parameters, worker_cap, variant = "streamed", now_fn)` (compute-only: the unchanged kernel resolves the parameters and the output schema on a zero-row template, then the exact declared rules run on the population through `produceDIAConfidenceTables`, one pass over whole protein groups for the bounded per-protein identification evidence lookup, then the rows streamed in source order with their global offsets; the template keeps a private configuration copy seeded from the saved state when no session bus or global configuration exists, as the family does since KIT-009) and `finishDIAReferenceQvalueStep(workflow, value, now_fn)` (the QC parameter record merged into the bus, the `qvalue_progress` product, the commit). Declaration `diaQvalueFilterOperation()` (unit `feature_group`, parameters `qvalue_threshold`, `global_qvalue_threshold`, `global_pg_qvalue_threshold`, `proteotypic_only`, `confidence_provenance_mode`; global statistics `protein_identification_evidence`, `source_row_offsets`; merge rules design/concatenate/sum). The step keeps its own product name, so the managed result reader and the peptide publication take the progress product by `workflowPeptideProgressProduct(record)` (`qc_progress`, else `qvalue_progress`) and the controller's completion routes a Q-value value to the step's own finishing step.
2. **The three remaining family sections as declarations** (`R/utils_workflow_dia_qc_rollup.R`): `diaPeptideProteinEvidenceOperation()`, `diaPeptideIntensityFilterOperation()` (global statistic `min_peptide_intensity_threshold`, audit A1) and `diaPeptideReplicateFilterOperation()`, each a kernel over `computeDIAReferencePeptideGroups` for its section with the family's `grouped`/`partitioned` variants (default `partitioned`); `runDIAReferencePeptideGroups` (GUI entry) now resolves the section's registry entry (`diaPeptideGroupOperations`), validates the parameters as the worker does and runs the registry's production variant; the family's descriptions live in `diaPeptideGroupDescriptions` so a worker needs none.
3. **Registry** (`R/utils_workflow_operations.R`, `R/utils_workflow_execution.R`): `peptide_qvalue_filter` (label `2_qval_filtered`, variant `streamed`), `peptide_protein_evidence_filter` (`3_protein_peptide_filtered`), `peptide_intensity_filter` (`5_intensity_filtered`), `peptide_replicate_filter` (`7_replicate_filtered`), each with its validator (`validateWorkflowPeptide{Qvalue,ProteinEvidence,Intensity,Replicate}Parameters`) and handler (`computeWorkflowPeptide{Qvalue,ProteinEvidence,Intensity,Replicate}Action`); compute, completion and publication roles `peptide` (no new role). The KIT-009 hand-off's `grouped` arm is kept as the adapters-only control arm of the family (no production caller; decision recorded here).
4. **Modules** (`R/mod_prot_qc_peptide_{qvalue,protein,intensity,replicate,impute}.R`): each server installs `installWorkflowManagedStep` for its operation (KIT-008 pattern): a managed application dispatches the apply to the managed worker and delivers the accepted product through the module's existing output updater; an unmanaged launch runs the same declaration in process; Revert cancels a running action; the plots carry the acknowledgement identity. The imputation module joins the pattern (KIT-009 left it in process). The intensity bootstrap takes the dispatch as its apply/revert observer seams and a plot identity.
5. **Harness** (`tools/profiling/workflow_kit.R`, `workflow_kit_coordinator.R`, `bindings-generator.R`): a ticket may bind `kind = "single"` with up to five `members` (operation, population, oracle, registry variant, parameters) on one `build`; cases `single-i` (role `single`, no control), selector `kit:0NN:single:N`, decision `kitSingleDecision` (every member eligible and verified exact against its journey oracle → `accepted`; a verifier refusal → `rejected`; any other rule → `invalid`; peaks, times and batches recorded, no ratio); `tickets$014` once `kit_014` is bound.
