## Findings

No probe reproduces a difference that D3 cannot absorb (P1, P2, P5: no stop). One draft finding from P4 (the lead's
row and number; F113-01 was used and dropped at review, so it is called F113-0x here):
  F113-0x (draft; R3; P4). The handler's value carries the annotation match results, which scale with the DA
  proteins (~416 B each by object.size). At W0's 16,000 x 300 x 3 the value is 6.76 MB of the acceptance's 8 MiB
  limit (:1772, object.size); above about 19,900 proteins the acceptance would refuse the result ("invalid_result")
  after the worker has computed, where in process the same Run completes. Fix inside D3, no methodology change: the
  handler saves the match results as an `rds` state value (as it saves the results) and the value carries the
  reference; the accept half hydrates it. Test first: a value-size test on a fixture whose match results exceed the
  limit (or the limit lowered locally) refused before the fix, accepted after, with the returned list identical.
Two observations for W2/W3 (not defects):
  - the transfer codec is `rds` (P1 (a)); the zero-row case rules out the display table;
  - the completion's pending provenance carries no values (P5). saveWorkflowEnrichmentState replaces it with the 9
    values right before its commit, so the clear D3 puts first matters when the accept half fails before that point:
    without it, the next commit would be attributed to `enrichment` with no values.
