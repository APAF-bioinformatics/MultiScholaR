**5.6**
> ### 5.6 Uncertainty, replicates, multiplicity
>
> - For S1, S3, F1, F2: the mean over data sets, its SD, Monte Carlo SE = SD / sqrt(R) and a t interval on R - 1 degrees of freedom; F1 and F2 are paired within a data set. For S2 in L12, L64 (2 families) and M12, M168 (3 families) the same on the per-data-set share. For S5 (one indicator per data set): Clopper-Pearson. Every table states R and the Monte Carlo SE beside each value.
> - **R = 400 per deciding condition.** *(r1.22: unchanged by the owner's decision on its operating characteristics, VAL-335, option (a); 40.1.)* Reason: S5's edge 0.01 can be met with zero events only if the one-sided 97.5 % Clopper-Pearson upper limit is below it: 1 - 0.025^(1/R) is 0.0092 at R = 400 and 0.0122 at R = 300 (**indicative** arithmetic). Operating characteristic: an arm whose true rate of attributable extreme errors per data set is p meets S5 with probability (1 - p)^400, which is 0.67 at p = 0.001, 0.37 at 0.0025 and 0.14 at 0.005 (**indicative**). 'Meets' therefore says that such errors are rarer than about 1 in 400 data sets. At a per-data-set SD of FDP of 0.05, R = 400 gives a one-sided 97.5 % margin of 0.005 and a Bonferroni margin of 0.0099 (t on 399 df at 1 - 0.025/576 = 3.97; 4.02 at 0.025/720); for S5 the Bonferroni lower limit is Clopper-Pearson at 0.025 / family, which reaches 0.01 at 15 events of 400 for every family size used here (**indicative**). Reported arms and Part M: R = 100 (data sets 1 to 100 of the same seeds, so they pair with the deciding arms).
> - **Family (Part L).** Deciding classifications: 3 arms x 4 cells x 3 masks x (N0, N1: S1, S2, S5; E0, E1: S3, S5) = 360 safety, plus 3 x 4 x 3 x (F2 in four scenarios, F1 in two) = 216 efficiency: 576. Under D6 (a), N2 and E2 at L12 and M12 add 3 x 2 x 3 x (5 safety + 3 efficiency) = 144: **720**. "Meets" uses each one-sided 97.5 % upper limit unadjusted (an arm is safe only if all its classifications meet: an intersection-union statement, valid without adjustment). "Fails" uses the one-sided lower limit at 0.025 / family (Bonferroni; 0.025 / 720 under D6 (a), 0.025 / 576 otherwise), so no single chance crossing declares a failure. Part P has its own family (18.5).

**38.2**
> ### 38.2 The rules in force (replace 5.7 and 35.3 where they differ; declared in `declaration.md`)
>
> 1. **Estimand (treatment policy, unchanged).** Every arm is scored on what the user receives: `uncorrected` assays as returned; a `dropped` assay's or a per-assay `no_da` assay's families as "no call" and its features as lost (5.4, 5.7).
> 2. **The 5 % gate.** Per arm and condition, a data set counts toward "no result" if its journey is `crashed`, `refused`, `no_da` (one assay or every assay), `dropped`, or a unit crash (an `arm = unit` row expanded to every arm and condition of its job). More than 5 % of R such data sets: the condition's classifications are **no result** and the arm cannot be safe there. `uncorrected` and LCm's `not_run` do not count. A data set absent from the declared range without a unit row stops scoring (instrument, 35.2). Since `crashed` and `refused` are now scored alike, `REFUSALS` (35.2 (4)) no longer changes any figure; classes are still recorded. **Gate first (r1.23; the coordinator's reading of VAL-335's "a data set enters at most one of the two", told to the owner):** a data set that is a phi event (an assay not corrected, no k) and then fails later in its journey (a crash, a refusal, no DA table) counts in this gate and not in phi; the overlap is reported per arm and condition as a column (`events_also_gate`).
> 3. **Journeys without a DA table** (`crashed`, `refused`, an empty DA table, a unit crash) are out of every estimand, S3 included: S3 is the mean FDP over the data sets where the arm returned a DA table (today's FDP 0 for them is removed). A journey with a DA table for at least one assay is scored as in 1.
> 4. **Best and worst case (reported, deciding nothing).** For each deciding classification of a condition with any data set out under 3, the classification is recomputed with those data sets included at best case (S1 0, S2 0, S3 0, S5 0) and at worst case (S1 1, S2 1, S3 1, S5 1); the condition is marked **"sensitive to failures"** when the two classifications differ. (The register's worst case names "any call, FDP 1, S5 1"; S1 at 1, every tested null called, is this specification's reading of "worst" for the null rate.) **(r1.23, SA-P13) On the oracle-excess path (5.7's oracle check):** the arm's data sets out under 3 are put at 0 (best) and at 1 (worst) for the estimand, paired with the oracle's value on that data set where the oracle has a DA table, and the paired excess is reclassified from them; it decides nothing.
> 5. **Paired comparisons on common data sets.** F1, F2, the oracle-excess classification of 5.7, and K1's LA-against-GA efficiency clause use only data sets where every arm compared and the oracle returned a DA table; the number of data sets dropped is reported per condition.
> 6. **The non-correction share phi** (per arm and condition, over the data sets whose journey reached the RUV step; r1.22, VAL-335; r1.19 wrote "over the R declared data sets"): a data set is an event if any assay was not corrected because the method could not: for LA (and LP, LAs, reported) an assay with `ruv_status` `uncorrected` or `dropped` and `ruv_k_found` NA (before KIT-242), or kept without RUV for a genuine no k (after KIT-242: `uncorrected` with `ruv_k_found` NA); for GA, factors `refused` (`omics_ruv_factors_refused`), not an estimated count of 0 (`none`).
