## Divergence from the ticket text, recorded

The ticket's item 1 says the summaries' `project_dirs` write goes the way the proteomics summary's did after KIT-013. It did not: `mod_prot_summary_publication_helpers.R` still writes `project_dirs` into `.GlobalEnv` (guarded on absence), `copyToResultsSummary`/`RenderReport` look the object up by name through `getProjectPaths(env = .GlobalEnv)`, and the lipidomics and metabolomics report templates themselves stop without a global `project_dirs` (`inst/reports/lipidomics/lipidomics_report.rmd:41`, the metabolomics twin). Nothing else in the application writes it (`setupDirectories` returns the list; the app server keeps it in `values$project_dirs`). Removing the summaries' write would have failed the report step of both lifecycle members. **Kept**, unchanged, in both summaries; allowed by name in the assertion test; handed to KIT-067 (the templates) with the proteomics site. The `globalEnv` parameter of the four summary helpers stays as the test seam the module-CI tests drive.

Two files outside the ticket's list carry the seam: `R/func_general_parameter_helpers.R` (`registerWorkflowOmicsBus`, `workflowOmicsProgressOwner`, `workflowScriptGlobal`, beside KIT-013's `workflowConfigEnvironment`) and `man/updateMetaboliteFiltering.Rd` (the two new arguments; `roxygen2` regenerated it; the unrelated manual pages and NAMESPACE lines `document()` also touched were reverted, the tree's docs being out of step elsewhere).

## Tests changed with the contract

The characterisation tests that pinned the old seams were updated to the new contract, none deleted: the plotting and duplicate-helper tests mock the helper in the namespace and plant a poison global of the same name (`test-lipid-03`, `test-lipid-10`); the design, import and summary tests assert no global copy (`test-lipid-13a`, `test-lipid-14a`, `test-lipid-15`, `test-metab-04`, `test-metab-05`, `test-module-ci-lipid-design`); the DA tests hold the state name and serve the object from the state-manager mock (`test-lipid-02ab`, `test-lipid-02b`, `test-metab-02aa`, `test-metab-02ab`, `test-module-ci-lipid-da`, `test-module-ci-metab-da`; the two harness mocks now keep saved states by name, the `WorkflowState` contract). `test-lipid-01` keeps the adapter's script contract (the global triple wins outside a session; the `omics_type` argument is still not consulted there).
