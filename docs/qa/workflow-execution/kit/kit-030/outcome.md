## Divergence from the ticket text, recorded

The ticket's item 1 says the summaries' `project_dirs` write goes the way the proteomics summary's did after KIT-013. It did not: `mod_prot_summary_publication_helpers.R` still writes `project_dirs` into `.GlobalEnv` (guarded on absence), `copyToResultsSummary`/`RenderReport` look the object up by name through `getProjectPaths(env = .GlobalEnv)`, and the lipidomics and metabolomics report templates themselves stop without a global `project_dirs` (`inst/reports/lipidomics/lipidomics_report.rmd:41`, the metabolomics twin). ## The one correction (the Study_report contrasts table)

The first `kit_030` install (`core/browser-smoke.3VPMfn`, 189f49fb) ran both lifecycle members to `lifecycle_complete_observed`; the project comparison against the KIT-068 members on kit_065 (same corpora, same journey; [compare-trees.py](compare-trees.py), [compare-content.R](compare-content.R)) found every DA long table, publication workbook and session RDS identical (cell contents; RDS with the `timestamp` fields masked), the PDFs and the `.docx` byte-different only by their embedded creation times, the volcano PNGs different only in `ggrepel`'s unseeded label placement (inspected), and **one real difference**: the lipid member's `results_summary/lipidomics/Study_report/contrasts_tbl.tab` had lost its header and `friendly_names`/`full_format` columns. Cause: `copyToResultsSummary`'s Study_report object copy re-resolves `contrasts_tbl` and `design_matrix` *by name*, in its calling frame, then the global environment, then the files, ignoring the tables it was given; the design builder's global copy had satisfied that lookup on kit_065, and with the copy gone the lipid run fell through to `contrast_strings.tab` (a headerless list). The metab run was spared only because its summary handler happens to hold the table under the name `contrasts_tbl` in the calling frame. Proteomics, without a global since KIT-013, has written the headerless fallback into its Study_report since then (checked on the kit_065 DIA_LIMPA replay project: `grouptreated-groupcontrol`, one line); the checkpoint proof's Summary check requires the file to exist and be non-empty and does not pin its content.

Repair (the ticket's own wording: the values "reach `copyToResultsSummary`/`RenderReport` through their existing argument path"): the object copy now uses the function's already-resolved `contrasts_tbl`/`design_matrix` first and keeps the by-name lookups as the fallback for other objects and scripts (`R/func_general_filemgmt_results_summary_helpers.R`, one block). Side effect recorded: the proteomics Study_report `contrasts_tbl.tab` gains its header and friendly names on the next proteomics install. One bounded correction: the helper fix committed, a second `kit_030` install, the two members rerun on it; the first install's members archived as `kit-lifecycle-(lipid|metab).kit030-attempt1-contrasts-fallback`.

The ticket's Simulation Setup names the e2e lanes' project files too. Those projects live in the app process's temp directory and are removed when the lane's app stops, so they cannot be hashed from outside; the lanes' own assertions on those files (design, contrasts, cleaned assays, DA tables) pass identically on both sides, and the GUI-path exactness is taken from the lifecycle members' projects below instead, the same journey on the same corpora on the two builds.
