## Shared definitions (once, in the first legend or the Methods)

- **Omics (simulators).** Proteomics, classic (S1); proteomics, DIA with limpa (S2; run on the `fastlimpadpc` engine); transcriptomics (S3); lipidomics and metabolomics (S4; one false discovery proportion per run over both assays).
- **Main scenarios.** Centre: 6 samples per group, 20% of features changed, one unwanted factor uncorrelated with the groups, 25% missing values where the omic has them, two groups. Each other main scenario moves one setting: 12 per group; 10% of features changed; no unwanted factor; no true effects (global null); factor correlated with the groups (ρ = 0.3); technical duplicates (4 units per group, 2 injections each); three groups. 1,000 simulated data sets per scenario and design.
- **Extra-hard scenarios.** 500 data sets each; they give conditions of use and were never used to judge a design.
- **Where the rows were run.** Main scenarios: one workstation, one pinned package version. Three designs added later (known null controls with the separation rule [22]; first-pass nulls with the estimated count [23]; first-pass nulls with the separation rule on their own controls [24]) were run on hosted cloud runners with the same package version and the same simulated data sets, after the two reference designs run there had reproduced the workstation's results (Methods). Extra-hard scenarios: workstation or hosted runner per scenario, never both (double dagger in Figure S8). The technical-duplicate scenario measured again: hosted runner, the repaired package version (section sign in Figure S2, filled square in Figure S3); it is shown as a scenario of its own beside the original, which stays marked as not judged.
- **Designs** (arm numbers of KIT-124 in brackets, for traceability; not on the figures). No RUV [1]. True factor known, the ceiling [2] (lipidomics/metabolomics: the true drift subtracted and the factor in the model). All features as controls, groups as replicate sets, factors in the model, k estimated [7]; the same with k = 1 [11]. Technical replicates as the replicate structure, all features as controls: factors in the model [16], corrected data tested [15]. Known null controls (50 true nulls, standing for a supplied list; internal standards in lipidomics/metabolomics), factors in the model [8]; the same, corrected data tested [10]; a control list in which 20% are true effects [9]. First-pass nulls: controls outside the 25% most significant features of a first test [5] (transcriptomics: RUVg) or with first-pass q > 0.5 [6], factors in the model. The rule for k behind the names: the known-null design [8] takes the estimated count and the first-pass design [5] the separation rule (the legacy design's k in the two proteomics routes and transcriptomics; the rule on its own controls in lipidomics/metabolomics); "known null controls, separation rule for k" [22] and "first-pass nulls, estimated count for k" [23] are the same two designs with the other rule, and "first-pass nulls, separation rule on own controls" [24; not run in lipidomics/metabolomics, where [5] already is that design] computes the separation rule on the first-pass controls. Legacy design [3]: controls are the least significant 5 to 30% of features and k is chosen by the separation rule; the test is on the corrected data in classic proteomics and lipidomics/metabolomics, is DIA's correction mode, and has the factors in the model in transcriptomics. Legacy controls and k with the factors in the model [4] (DIA: the covariates mode; transcriptomics: identical to the legacy design, not run separately). Other methods: RUV-4 [12] and RUVinv [13] with the known nulls, surrogate variable analysis [14] (transcriptomics: svaseq, and svaseq with the k of the RUV designs [14E]), RUVr [R], pooled QC injections as the replicate set [Qs corrected data tested, Qm factors in the model], internal-standard normalisation only [I], QC-based LOESS drift correction [L], the known batch in the model [17, known-batch scenario only].
- **Colours.** One colour per design in every figure (Okabe-Ito): grey no RUV, black ceiling, green all features as controls, sky blue technical replicates, blue known null controls, orange first-pass nulls, vermillion legacy; a lighter or darker tint is the variant of the same family; purple other methods; mid grey other designs.
- **Reference lines.** Solid: the nominal level, 0.05. Dashed: the limit of the pre-specified decision rule, 0.075 (rule 1 for the type I error rate, rule 2 for the mean false discovery proportion).
- **Not judged (dagger, cross or faded).** Scenarios in which the ceiling design itself failed rule 1 or 2, so that no design was judged there: technical duplicates in transcriptomics and in lipidomics/metabolomics (the package fits technical replicates as independent samples in these omics), and the global null in lipidomics/metabolomics (an effect of scoring both assays as one family). The technical-duplicate scenario was measured again after the package was repaired (below, Figure S2); those rows are not void, and by the pre-specified rule the scenario stays "reported, not used to judge" in these two omics.
- **Numbers on axes and in cells** are written without the leading zero (.05 = 0.05).
- **Subset.** Each design is shown on its primary feature set: all features, or the features complete in every sample for RUV-4, RUVinv and surrogate variable analysis in classic proteomics and lipidomics/metabolomics.

## Figure S2. Calibration of every design in every main scenario (three parts)

Files: `figS2-calibration-heatmap-part1` (proteomics, classic; proteomics, DIA), `-part2` (transcriptomics) and `-part3` (lipidomics and metabolomics).

Mean false discovery proportion among the features called at q < 0.05 (nominal 0.05), for each design (rows) in each main scenario (columns), one panel per omic; 1,000 simulated data sets per cell. The value is written in each cell. Each panel lists the designs that were run in that omic, in the same order everywhere; the coloured square beside a design is its colour in the other figures. Colour of the cells is the ratio to the nominal level on a log scale: white at 0.05, blue below (conservative), red above (liberal), clipped at 0.0125 and 0.8. Empty cells: the design was not run in that scenario (designs with technical replicates were run in the technical-duplicate scenario only; the contaminated control list was not run under the global null in the two proteomics simulators). † scenario not judged: the ceiling design itself failed (see shared definitions). § "Technical duplicates, repaired package": the technical-duplicate scenario of transcriptomics and of lipidomics/metabolomics measured again on the repaired package version, on a hosted runner, for no RUV, the ceiling and all features as controls (lipidomics/metabolomics: also the two designs with technical replicates as the replicate structure); the other designs were not run again. In transcriptomics the repaired package sums the two libraries of a unit before the analysis (8 samples), the designs with technical replicates cannot be formed, and the ceiling's factor is the mean of a unit's two library scores, an approximate ceiling. The three designs added later (rows "separation rule for k", "estimated count for k", "separation rule on own controls") were run on hosted runners on the first package version, so in transcriptomics and lipidomics/metabolomics their technical-duplicate values are in the void column, not in the repaired one. In the global-null scenario the false discovery proportion of a data set is 1 if any feature is called, so the mean equals the share of data sets with any call.

## Figure S7. Number of unwanted factors: estimated against true

File: `figS7-factors-estimated-against-true`.

Number of unwanted factors removed (k) under the two rules, as they were run: left, the estimated count (`sva::num.sv`, permutation method, 20 permutations) in the design with all features as controls (one estimate per data set, shared by every design that uses it); right, the separation rule in the legacy design. Each cell is the share of the 1,000 data sets of a main scenario (columns) in which k took the value of the row; shares under 0.005 are written <.01 and cells without a data set are empty. Outlined: the true number of unwanted factors of the scenario (1; 0 in the scenario without an unwanted factor; 2 in lipidomics/metabolomics, drift along injection order and one sample-wise factor). In lipidomics/metabolomics k is the mean over the two assays, hence the half steps. Values of 5 or more share one row. † scenario not judged in the other figures (the count of factors does not depend on the test). The first-pass-null designs take the legacy design's k in the two proteomics routes and in transcriptomics; in lipidomics/metabolomics they apply the separation rule to their own controls (mean k in the results table).

Values for the text. Where a factor exists the estimated count equals the true number in 99.4 to 100% of data sets in the two proteomics routes and in transcriptomics, and in 92.7 to 99.9% in lipidomics/metabolomics; it exceeds it in under 1% of data sets in the proteomics routes and in none elsewhere. ## Figure S9. Null check on public real data

File: `figS9-real-data-null-check`. Table: `tableS-real-data-null-check.csv`.

One public data set per omic. For each split, 12 biological units of one condition were drawn and put into two false groups of 6, so every p below 0.05 and every call is false; 100 splits per kind of split, one attempt. Random splits in all four omics; in DIA and in metabolomics also splits aligned with the recorded batch (4 units of one batch and 2 of the other against 2 and 4: a correlation of 1/3 between batch and false group). Designs: no RUV, the recommended design (all features as controls, factors in the model) and the legacy design; in DIA the legacy design in its two forms (corrected data tested; and "legacy controls and k, factors in model", the route's shipped default). Colours as in the other figures.

Left panels: share of features with p < 0.05. Black point: mean over the 100 splits; thick bar: 5th to 95th percentile of the splits; thin line: their range (the splits share samples, so these describe the splits and are not bounds on the mean). Open diamond: the same design in the simulated scenario that stands beside the split (random splits: the global-null scenario; batch-aligned splits: the scenario with the factor tied to the groups, ρ = 0.3). Solid line: nominal 0.05; dashed line: the limit for the mean, 0.075. Square-root axis. Right panels: number of the 100 splits with any call (bar, and the count at the right); tick: the design's limit, twice the count of no RUV on the same splits or 10, whichever is larger; open diamond: the share of simulated data sets with any call in the global-null scenario, where one exists (none for the batch-aligned splits, whose simulated counterpart has true effects, and none for lipidomics/metabolomics, whose global-null scenario is void). Both limits were declared before the runs.

"Contradicts the simulation": the one row in which the real data and the simulation disagree by the rule declared beforehand. No RUV in DIA was scored "failed" in the simulation (type I error rate 0.116 with the factor tied to the groups) and is within both limits on the real data, on both kinds of split.

Bottom panel, a bounded check of one reading of that disagreement: how strong the labelled unwanted variation of the DIA data set (its two culture batches) is against the simulated factor. Ten matrices of 12 samples per source, quantified the same way. Filled points: median over the ten matrices, with their range, of (left) the share of a protein's variance explained by the factor, at the median protein, and (right) the factor's share of the matrix's total variance. Open points: the same with the factor permuted, the floor at 12 samples. Every real matrix is below every simulated one on both measures. The check measures strength in one data set; it does not show that strength is why no RUV stays within the limits there.

## Table S (per-scenario results), `tableS-per-scenario-results.csv`

One row per omic, scenario, design and feature subset (`primary` marks the subset shown in the figures). Columns: identifiers (`omic`, `simulator`, `scenario_class`, `cell`, `scenario`, `design`, `tier`, `arm`, `subset`, `primary`, `state`, `platform` laptop or runner, `package_tree`, `legacy_platform_dependent`, `not_judged`, source `folder`). The cell code `C6R` is scenario C6 (technical duplicates) measured again on the repaired package version (`package_tree` ace1f4de, folder `r0a-gha`); the rows of code `C6` in transcriptomics and lipidomics/metabolomics are the originals and are void. `legacy_platform_dependent` is true for the legacy design's rows of the extra-hard scenarios run on hosted runners. Further columns: counts (`runs`, `scored`, designed and method refusals, crashes; a refused run carries its data set's no-RUV result); `mean_k`, the mean number of factors removed; the type I error rate at 0.05 (`null05`) and 0.01 (`null01`), the mean false discovery proportion (`mean_fdp`), power, bias and root mean square error of the log2 differences of true effects, each with its Monte Carlo standard error and, where given, mean ± 1.96 standard errors (`_lower`, `_upper`); the share of data sets with a false discovery proportion above 0.10 (`fdp10_share`) and with any call (`anycall_share`) with exact one-sided 97.5% bounds; the status of each decision rule (`rule1` to `rule7`), rule 3's limit and the row's verdict, as scored by `kit-124/aggregate.R`.

One row per decision rule (1 to 7) and one each for the bounds, void scenarios and the verdict of a design. ## Table S (conditions of use), `tableS-conditions-of-use.csv`

One row per omic, extra-hard scenario and design of the option set (the two references, the recommended design, the same with k = 1, known null controls, first-pass nulls, the legacy design, and the known batch in the model where it was run). Transcribed from the final scoring's own side-by-side table (`kit-124/scored/final-20261118/option-arms-extra-hard.tsv`): data sets, refusals, crashes, mean k, type I error rate at 0.05 and 0.01, mean false discovery proportion, the share of data sets above 0.10 with its bounds and rule 3's limit, power, the status of rules 1 to 6 as scored, whether the ceiling passes rules 1 and 2, `void`, the platform, and the mark for the legacy design's platform-dependent rows. Two columns are added and nothing is computed again: `rules_not_passed` lists the rules 1 to 6 whose status is not "pass"; `reading` applies the rule stated with the final scoring to those statuses: "void" where the ceiling fails rule 1 or 2; "within every limit" where rules 1 to 3 pass and rule 4 (or 5), where it applies, is not failed; "outside a limit" where one of rules 1 to 5 is failed; "inconclusive" otherwise. Rule 4 is not read for no RUV (it cannot gain over itself) and rule 6 (crashes) is listed, not read. For no RUV, the recommended design, known null controls, first-pass nulls and the legacy design the counts per omic agree with the final scoring's own summary (`kit-124/outcome.md`, "Conditions of use per omic"), which was compared row group by row group.
