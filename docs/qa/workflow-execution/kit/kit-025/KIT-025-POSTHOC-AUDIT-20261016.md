# KIT-025 post-hoc audit (2026-10-16, audit only)

Mode `post_hoc` against the ticket at revision 1.3, the analysis-record audit's remediation (AR-01..04, AR-16, AR-17) and the plan's record-invariance rule. Scope: the implementation at `23c9c8b2` (+ the runner follow-up `03a33b70`), its tests, the in-process check and the install. Findings before any repair; nothing is changed by this audit.

## What was checked beyond the outcome's own claims

- The head's size bound: the 65,536-byte limit is on the head pointer file, not the snapshot value; `publishDIAStateHead` and `saveDIAStateValue` impose no snapshot cap, so the per-build environment table (about 20 KB, 155 package versions, once per build) and the per-state entries (about 300 bytes) are not near any limit.
- The lifetime of the pending-provenance slot, read against the DA wrapper (`runSavedOperation` per contrast, then `publishDIAStateHead`, no state commit) and the modules' in-process branch (`workflowSessionApplication(session)` NULL → the reference wrapper runs in process, no setter).
- `workflowSoftwareIdentity()` cost: 80 ms per call under a source load (155 `packageVersion` reads), called at every commit.
- The provenance check's coverage: the fixture's states are all `legacy` by construction, so the "registered operations resolve" and "parameter names match" results are vacuously true on the fixture; the registered paths are covered by unit tests only (worker completion via the fixture entry, the runner's pending slot, the design builder's name).
