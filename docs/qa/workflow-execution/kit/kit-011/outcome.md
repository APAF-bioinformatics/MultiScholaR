# KIT-011: on-disk state manager, native sessions and import adoption by default

Status 2026-10-11: **implemented; the journey pair is declared and waits for the user's go.** Authority: `tickets/kit/00-KIT-PLAN.md` (run ledger KIT-011: two journey members, journey ceiling; reordered ahead of KIT-009/010 by the user 2026-10-11); protocol v1.3; the KIT-005 acceptance as amended by the user ("later comparisons against the production default are completion plus those per-step peaks"). Control: `kit_006` (`core/browser-smoke.qBR5tm`), run as users run it (no launch record).

## What changed

- **The on-disk path is the DIA default.** `isDIANativeDefaultEnabled()` is TRUE: `initializeDIANativeImport` attaches the on-disk owner at DIA-NN import (Linux, IQ route) without the `multischolar.dia_native_sessions` option; the journey launch record no longer sets that option (its `native_sessions` flag stays recorded for the harness). Platform limits unchanged: Limpa, non-DIA-NN formats and non-Linux keep the in-memory `WorkflowState` (claim limit, audit B25).
- **The capacity trial is gone.** `initializeDIACapacitySession`, the `multischolar.dia_capacity_trial` option, the non-exact capacity rollup arm (`computeDIACapacityRollup`, the `sql_rollup` branch of `runPeptideRollupApplyStep`) and its feeders (`prepareDIACapacityRollupInput`, which wrote a rollup-input entity and envelope after every protein-evidence filter, and `getDIARollupEnvelope`) are removed (hand-off item 7). The adapter's precursor rollup is the reference path (`runDIAReferencePrecursorRollup`, P14 under the kit). `reference_states` is no longer derived from the session format anywhere. Memory reclamation (`reclaimDIACompletedMemory`, `reclaim_enabled`, default FALSE at adapter creation) stays reachable; its default is a decision for KIT-012 (audit B26).
- **Sessions.** `openDIANativeSession` / `runDIANativeSessionExport` are the DIA Save/Open path by default (the export and the legacy-session ingest were gated on the same flag); the legacy v1 archive still opens through `ingestDIANativeLegacySession`.
- **References.** `savedReactiveVal` is the omic-agnostic name of `newDIASavedReactiveVal`; the protein-S4 revert goes through `selectDIAStateReference` (a reference on the adapter, hydration on the in-memory manager). The history list is still cut back on revert (audit C6).
- **Harness.** A ticket journey pair (`kit-journey-011`: `control-1` on `kit_006`, `candidate-1` on `kit_011`, both without a launch record), `kitJourneyTicketDecision`, and a verifier branch that checks a record-less member whose build stores states on disk against the KIT-005 `journey_<step>` oracles. The driver's `capacity_treatment` options in `workflow_checkpoint_dia_driver.R` (CORE-pinned, not edited) are now inert.
- **Tests updated for the new default**: the two import module tests read the holders through `getDIAOwnedPayload` and mock the GUI config reader (the native route's seam); the two owner-diagnostics tests build the adapter in the retired trial's context (legacy format) directly; the native-session test drops the `FALSE`-option arm; the saved-rollup envelope test (removed arm) is removed; the lifetimes peptide-apply test no longer expects the rollup-input preparation.
