# KIT-104 notes for phases C and D (W5, W6, W7), from the W1 to W4 reports (2026-11-08; the lead's copy)

## The QC core (W2)
- **Finalise check:** validateWorkflowOmicsQcFinalize(shell, config, binding), where config = omicGuiConfig(<omic>)$qc and binding = the declaration binding (class, data_slot). It takes three arguments because the class is not in the qc group. The mismatch text is 'Current <Class> object has assay/design mismatch: ' plus the errors joined by '; '. A qc config with no finalize_alignment is refused (omic_gui_config_invalid).
- **QC action:** runWorkflowOmicsQcAction(binding, workflowData, step, deliver, draw, failed).
  - deliver(result, figure), where result = list(value, reference). Call figure() where today's tab draws, inside its tryCatch that logs 'Could not generate QC plot:'.
  - On a runner, figure() reads the worker's metrics; NULL metrics fail with 'the worker computed no filtering metrics'. In process, it draws from list(theObject = state).
  - draw(arguments) should do.call the config's filtering_figure with step_name, omics_type, return_grid = TRUE and overwrite = TRUE.
  - failed applies only on a runner; in-process errors propagate to the observer's tryCatch.
- **ITSD:** analyzeWorkflowOmicsItsd(binding, manager, pattern, itsd) returns list(metrics, long_data, result_text, total, pattern, metrics_by_assay). When there is no long data, metab sets is_data_long to NULL while lipid kept the previous value. The core returns NULL, so the shared sub-tab chooses; metab's behaviour is recommended (it differs only when standards are found but no intensities can be read).
- **Duplicates:** detectWorkflowOmicsDuplicates returns list(duplicates, total). total is an integer (lipid's was a double), with the same text. omicsDuplicateResolutionStats(value, assay_names).
- **Missing state:** the core uses shiny::req(shell), as lipid and metab do.
