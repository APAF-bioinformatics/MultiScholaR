# KIT-004: operation runner and the whole-matrix declarations

Status 2026-10-10: **complete.** No counted member. One recorded in-process comparison on the screen fixture (three passes) and one identity-continuity check against the KIT-001 member store. Authority: `tickets/kit/00-KIT-PLAN.md`; protocol v1.1. Step map: `normalisation_ruv`, `correlation` and `da` are `whole_matrix` with code evidence and no open flag (`../kit-001/step-map.json`, 0 open flags), so the three declarations were allowed.

## What changed

- `R/utils_workflow_operations.R` (new): `newWorkflowOperation(name, input_class, fields, columns, unit, kernel, output_class, parameters, product_type, global_statistics, merge, factors)` with `validateWorkflowOperation` (unit in `row | complete_sample | feature_group | whole_matrix | store`; input and output classes must be in the KIT-002 registry; hydrated fields must be stored by the input class; `merge` rules required exactly when the unit is partitioned, values `design | concatenate | sum`; `global_statistics` a named vector). `runSavedOperation(manager, declaration, source, parameters, dependencies)`: identity through `diaComponentScientificIdentity` with the declaration's name and the declared parameters in declared order; `resolveSavedWorkflowEntity` with the declaration's factors; on a hit the saved product is returned without computing; on a miss `runProjected` hydrates one projected object (`readDIAExecutionComponents(fields, columns)`), the declaration's `kernel(object, parameters, store)` runs, and the value is saved as the product under the identity and rooted on the source, the caller's dependencies and every reference the store handle created. The store handle checkpoints an S4 only if it is the declared output class (`workflow_operation_output`), inherits the source for the checkpoint record, saves tables as components and derived products under the derived identity (`selectors` digested with the product name, as before). Refusals are typed: `workflow_operation_invalid`, `workflow_operation_source`, `workflow_operation_parameters`, `workflow_operation_input`, `workflow_operation_output`, `workflow_class_undeclared`.
- `R/utils_workflow_dia_products.R`: `diaNormalizationOperation()` (`normalization-ruv`; normalisation and RUV stay one declaration producing `dia-normalization-ruv`; the normalised object is checkpointed as `normalized-science` before RUV and the corrected object inherits it, as before), `diaPearsonPairsOperation()` (`pearson-pairs`, a product) and `diaPearsonSelectionOperation()` (`pearson-selection`, the checkpointed object's reference). `runDIAReferenceNormalization(settings, ...)` and `runDIAReferenceCorrelation(..., threshold, skipped, ...)` are thin shims that call the runner, commit the state and publish the outputs. The `config_list` write, the completion notification and the RUV audit trail moved to `runProtNormNormalizationWorkflow`; the correlation completion (`completeProtNormCorrelationWorkflow`: summary render, notification, GUI state) moved to the two correlation observers.
- `R/utils_workflow_dia_da.R`: `diaContrastOperation()` (`DA-contrast-output`, factors `route = iq, layer = contrast_references`, parameters `formula, qvalue, lfc, weights, contrast, annotations`): the unchanged `differentialAbundanceAnalysis` on one projected object; result tables become components and the display values derived products, assembled into the existing `dia.contrast_reference.v1` record. `runDIAReferenceDaAnalysis(settings, da_data, workflow, paths, contrasts, annotations)` loops the contrasts through the runner, keeps the manifest, args commit and output publication. The `.GlobalEnv` fallbacks for `contrasts_tbl` and `uniprot_dat_cln`, the three `updateSelectInput` calls and the notifications moved to `da_server_run_analysis_handler`.
- `R/mod_prot_norm_ruv_helpers.R`: `resolveProtRuvParameters(normalizedS4, settings, ruvGroupingVariable)` is the kernel-only RUV parameter determination (automatic: `findBestNegCtrlPercentage`; manual: `getNegCtrlProtAnova`, `ruvCancor`, `buildProtNormManualRuvResult`, with the same tolerated cancor failure; `validateProtNormRuvK` in both). The module keeps `resolveProtNormRuvParameters` and `runProtNormBetweenSamplesStep` unchanged as the legacy-path adapters (audit B5).
- Grep evidence: no `input$`, `.GlobalEnv`, `shiny::`, `showNotification`, `updateSelectInput`, `withProgress` or `session$` in `R/utils_workflow_operations.R`, `R/utils_workflow_dia_products.R`, `R/utils_workflow_dia_da.R` (the `rootDIAProduct` loop variable was renamed from `input` to `root` so the grep is clean).
- Four test call sites updated for the shim signatures (`notify`, `output` and `session` arguments removed); the native-session cycle test now performs the correlation completion the module edge performs.
