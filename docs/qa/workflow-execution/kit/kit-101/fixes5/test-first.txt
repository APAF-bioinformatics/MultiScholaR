== The sites ==
Every QC sub-tab observer in lipid, metab and trx that applies or reverts a QC step is created when the QC
orchestrator starts its sub-modules (the design's qc_trigger, or the state-detected start). Each was driven as F-17's
block drives the trx filter: the orchestrator (mod_lipid_qc_server; mod_metab_qc_server; mod_lipid_qc_server under
trxOmicProfile()) with the design's trigger, the workflow's state manager unset before the design, the head at the
design's state (initial, <omic>_raw_data_s4). The button is clicked (1) before the trigger; the design is saved
(state manager set, trigger TRUE); then clicked again (2).

Not changed (outside the apply/revert class; recorded): lipid and metab "Detect duplicates" (detect_duplicates) and
"Analyze internal standards" (analyze_is). They also run an earlier click when the sub-modules start (seen on the base
with the same drive), but they commit no state: they fill the tab's display only.

Cause: as F-17. The sub-module servers start at the design; each observeEvent is created then without ignoreInit, and
its first run reads the click value already present, so a click made before the start runs at the design: a revert
drops the design's state (history back to "initial"), a finalise marks QC complete, an apply or resolve commits its
state, none of them requested after the start.

Fix: F-17's rule, now one small helper used by every site (F-17's inline lines replaced): qcClickAfterStart(input, id)
records the button's value when the server starts and the observer ignores that value; a later click runs as before.
ignoreInit = TRUE is not used (F-17: it also drops a first click made in the same flush as the start). The helper
records a value only from a live Shiny input: the register* seams are called by their tests with a plain list holding
the click and a stub observeEvent that runs the handler at once, which is not a click before a start.
