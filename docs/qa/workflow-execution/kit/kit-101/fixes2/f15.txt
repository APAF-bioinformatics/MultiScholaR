Diagnosis
  Raised by readComponentMetadata (R/utils_workflow_dia_state.R) when the checkpoint's class is not in the
  accepted list. buildWorkflowAnalysisRecord (R/utils_workflow_analysis_record.R) read every state in the
  history through readWorkflowStateMetadata, which accepts only the declared ASSAY classes.
  The proteomics enrichment commits `enrichment_completed` with manager$saveState(..., EnrichmentResults, ...).
  On the reference-state owner, an S4 value is checkpointed by checkpointWorkflowExecutionResult and committed
  by commitWorkflowReferenceState. That is the same path every other committed state takes, giving a complete
  dia.component_checkpoint.v2 of the declared RESULT class `EnrichmentResults` (KIT-003). A result class
  requires no assay or design component (workflowClassRequiredComponents), so the checkpoint is complete for
  its declaration. The state carries everything its declaration requires, and restoring it
  (restoreProtEnrichResultsFromState, test-workflow-dia-products.R) works.
  The DA commits no state (a manifest only), so `enrichment_completed` is the only result-class state a head
  can carry. The builder's assay-only read was therefore wrong for this state. Before F-08 was fixed, DA failed
  and enrichment never ran, so the path was never reached.
  Changing the enrichment commit was rejected: making it an assay checkpoint would change the enrichment
  product and its restore.

Fix (R/utils_workflow_analysis_record.R, buildWorkflowAnalysisRecord only)
  1. The per-state read uses readComponentMetadata(manager, reference), which accepts every declared class.
     For an assay-class state this is the same function with the same checks, so its record is unchanged.
  2. The record's `design` is taken from the last state whose checkpoint is not a declared result class,
     because the enrichment state has no design. Every record that could be built before had no
     result-class state, so its `design` source is unchanged.
