== F-09  tests/testthat/test-module-ci-prot-dia-limpa.R ==
New block: "KIT-101 F-09: before the peptide stage has made its state, the DIA_LIMPA protein
sub-tabs refuse naming it". An on-disk owner holding the import's peptide state (no log2 matrix,
no quantified protein state); the three apply observers (dpc_quant, normalisation, peptide_count)
run with their production step functions; notifications captured.

Cause: KIT-048 made the three in-process steps (runProteinDpcQuantStep, runProteinNormalisationStep,
runProteinPeptideCountStep) call their reference runner with `parameters`, a name bound only in the
module observer, so every unmanaged apply failed with "object 'parameters' not found" whatever the
state. Fix: each step builds the runner's parameter list from its own arguments; the normalisation
and peptide-count declarations name the state they need (readDIAReferenceProteinObject takes the
refusal text; its default, used by every other caller, is unchanged). DPC already named its input.

== F-10  tests/testthat/test-prot-05b-norm-module-contracts.R ==
New block: "KIT-101 F-10: the normalisation tab warns that QC is incomplete only while it is".
runProtNormTabEntryWorkflow (the tab-entry observer's body) on the normalisation tab, the warning
and the pre-QC generator captured.

Cause (the stale read): the entry gate shouldProtNormAutoGeneratePreQc is FALSE both when the state
is not a normalisation state and when `normData$pre_norm_qc_generated` is already TRUE; the
workflow treated every FALSE as "QC incomplete". So every re-entry of the tab after the first
(the entry lanes re-select the tab before each action) warned "Please complete the Quality Control
filtering steps before accessing normalization." with QC complete. It also warned on a route whose
last QC state is not in the trigger list (DIA_LIMPA: peptide_count_filtered) with QC complete.
Fix: warn only when the state is not a normalisation state and tab_status$quality_control is not
"complete"; otherwise return quietly. Generation and its trigger states are unchanged.
