== F-17  tests/testthat/test-module-ci-trx-qc.R ==
New block: "KIT-101 F-17: a filter click made before the QC sub-modules start is not run when they start". The QC
orchestrator as the transcriptomics module starts it (mod_lipid_qc_server under trxOmicProfile(), with the design's
trigger) on an owner holding trx_raw_data_s4; the workflow's state manager is unset (before the design, the tab has
no state and the sub-modules wait for the trigger). The filter is clicked (apply_filter = 1), then the design is
saved (state manager set, trigger TRUE). The history must not gain trx_expression_filtered; a second click then runs
the filter.

Cause: mod_trx_qc_filter_server is started only at the design (qc_trigger); its observeEvent(input$apply_filter) is
created then and its first run reads the click value already present, so it ran the earlier click.

Fix: the server records the click value present when it starts and its observer ignores that value; a later click
runs the filter as before. No message is shown (lipid and metab show none either).
Not used: ignoreInit = TRUE (the dispatch's suggestion). It also drops the first click of a server that is started
and clicked within the same reactive flush, which is how MCI-028.1/.2/.3 and the F-11 block drive the module:
with it those four blocks failed ("The test referenced an output that hasn't been defined yet:
output$filter-filter_results"; COUNTS pass 12 fail 1 error 3). Note: the lipid and metab QC apply observers are
also created without ignoreInit (mod_lipid_qc_intensity_server_helpers.R:127, mod_metab_qc_intensity.R:358) and
start at the same trigger; not changed here (outside the finding).

== F-20  tests/testthat/test-prot-05b-norm-module-contracts.R ==
New block: "KIT-101 F-20: on the DIA_LIMPA route the tab recognises the completed protein QC". The tab-entry
workflow (runProtNormTabEntryWorkflow) entered with the route DIA_LIMPA, the QC tab status as the route leaves it
("pending" or "in_progress"), and the head at the protein QC's last state (peptide_count_filtered) or the tab's
RUV covariates state (ruv_covariates): no warning, no pre-normalisation QC generation. Kept: a DIA_LIMPA head
before the end of the protein QC (protein_dpc_quant, protein_normalised) warns; the DIA route is unchanged.

Cause: F-10 (1ecd454c) stops the warning when the QC tab status is "complete", but the DIA_LIMPA route never writes
that status: mod_prot_qc_server marks QC complete when protein_replicate_filtered is reached, and the limpa protein
stage ends at peptide_count_filtered. Neither that state nor ruv_covariates is in the tab's trigger-state list.

Fix: on the DIA_LIMPA route a head at peptide_count_filtered or ruv_covariates counts as QC complete for the warning.
Nothing else changes (no QC generation, no tab-status write).
