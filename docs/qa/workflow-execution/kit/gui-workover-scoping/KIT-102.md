## 6. Risks

1. **Selectors and keys are contracts.** All of these are read by the e2e helper (`helper-e2e-browser.R:782-849, 908-910`), the harness or `collect_state_digest`; every one must come from config. Changing any of them changes a journey.
   - the tabset ids;
   - the tab values and module ids;
   - the test ids (`lipid-tab-import`, `prot-tab-setup`, `lipid-import-*`, `metab-import-*`, `trx-import-*`);
   - the input ids (`lipid_id_col` versus `metabolite_id_col`; `exclude_norm` lipid only);
   - the status keys (`differential_analysis` versus prot's `differential_expression` and `enrichment_analysis`);
   - the `column_mapping` keys (`lipid_id_col` or `metabolite_id_col`; 25 and 23 R files name them);
   - the `processing_log` keys;
   - the summary file names;
   - the notification texts.
2. **Hidden behaviour differences** that a shared implementation would unify:
   - metab import leaves `design_matrix` `disabled` (`mod_metab_import_processing_helpers.R:301-303`), while lipid (`mod_lipid_import_processing_helpers.R:307-312`) and prot (`completeProtImportSuccessState`) set it `pending`. The digest shows this (D2).
   - The assay-name rules and messages differ (D3).
   - The error return differs: lipid returns `NULL`; metab returns `list(status = "error")`, and MCI checks `run$result$status`.
   - Metab's second assay is always MS-DIAL.
   - The trx bus `data_type` is overridden after the lipid commit (`mod_transcriptomics.R:135-138`).
3. **Proteomics is not the light pattern at import.** All reading, FASTA processing, organism analysis and configuration loading run inside one observer (`mod_prot_import_server_helpers.R:273-426`). The reader takes the Shiny `input` (`processing:38-77`). The `releaseDIAWorkingReference` sequence (333-347) is a measured memory boundary and must move unchanged. The proteomics top-level shell is the weaker template: an `exists()` guard per tab, and five hand-written observers. The pattern worth keeping is proteomics' owner and managed-step architecture, not its GUI.
4. **The import reads the assay in the application process.** This is accepted today: the import is not a managed step, and KIT-082 covered the steps after it. The move must not add a copy: keep one table on `localData` and one on the bus by reference.
5. **The parity conversion for trx** must run before `validateTrxCounts`. Otherwise a text column is refused as "counts must be numeric", not converted (`func_trx_counts.R:30`).
6. **Exported API.** Keep the 14 exported module and launcher names (`mod_{lipidomics,metabolomics,proteomics}_{ui,server}`, `mod_{lipid,metab,prot}_import_{ui,server}`, `run_{lipidomics,metabolomics}_app`) as wrappers. `render_workflow_stepper`, `collect_state_digest` and `run_app` stay unchanged. Deprecating any of them is out of scope.
7. **Transition size.** If the old copies are deleted only in KIT-109, KIT-102 adds about 1,300 lines temporarily (shell, config, shared import and core), and the profile hooks and old modules coexist (D5).
8. **Not in scope.** The landing tiles in `app_ui.R` and the debug `message()`/`print()` noise in `app_server.R:418-490` are unrelated; leave them.
