Duplication measured (names normalised, comment lines dropped):
- **Builder UIs:** lipid and metab are code-identical (a 1-line difference, a blank line). All three builder UIs (lipid, metab, prot) expose the **same 38 namespaced input/output ids**. Prot differs in layout formatting and adds `prot-design-*` test ids.
- **Validators:** lipid and metab differ in 3 places:
  - lipid has `lipidDesignResolveFormulaString`; metab inlines the fallback;
  - the non-sample regex lists differ (lipid adds `^Name$`, `^Annotation$`, `^Class$`, `^Category$`, `^Subclass$`, `^Main class$`, `^Ion mode$`; metab has the prefix `^Annotation`);
  - the omic label in every error message.
- **Builder servers:** metab's closure is the lipid helpers inlined. Each of these is line-for-line the same algorithm in all three omics: metadata assignment, tech-rep consolidation, contrast append, sample removal, the tech-rep summary text and the save payload. The difference is the column-mapping key (`metabolite_id_col` vs `lipid_id_col`). Proteomics runs the same design-matrix algorithms, but its data operations (rename, subset, initial runs) act on a long DIA-owned table through `transformDIADesignTable`.
- **Commits:** lipid `runLipidDesignBuilderObserverShell` and the metab inline flow are the same sequence (preflight, bus, files, object, bind, provenance, `saveState`, QC trigger, tab status). They differ in two places (section 6, R2).

**Run order must stay per omic and recorded.** It sets the design's row order. Through `buildLipidDesignSaveResultsDataList` it also sets the assay columns' order: `intersect(designMatrixFinal$Run, names(assayDf))` reorders the columns to the design. The S4 object inherits both. Downstream sums over samples (edgeR library sizes and TMM, limma fits, RUV SVD) are order-dependent in the last bits. KIT-098 showed that aligning by name gives 13 of 21 identical kernel products on trx_screen, and it built the second notebook reference on the counts-file order. The current rules:
- **lipid, metab, prot:** the fresh design is `mixedsort`;
- **trx:** the fresh design is the input order;
- **imported designs:** file order;
- **prot TMT/LFQ:** the object's columns follow `pivot_wider`, which is the long table's first-appearance order, not the design.

So `run_order` must be a required per-omic field with no shared default. KIT-103 must record each omic's rule in its evidence, and the entry suite should assert the fresh-design `Run` order for every omic, as MCI-027.1 already does for trx. **Decision needed:** recording the rule in the `design_builder` provenance would change the analysis record that the v1.7 / KIT-098 oracles cover. Recommendation: record it in the config and the evidence only, unless the user asks for provenance.

## 6. Risks

- **R1 Run order (bit-wise).** See section 3. A shared default, or applying `run_order` in a new place (the existing-design path, the dropdowns' `mixedsort`, the save subset), changes results. Pin it with fresh-design and saved-`data_cln` column-order assertions per omic.
- **R2 Commit divergences, lipid vs metab.** On an invalid preflight, metab `stop()`s inside the observer (an observer error), where lipid shows a notification and returns. Metab also writes the bus (design, `data_cln`, contrasts, config) **before** checking `source_dir`; lipid checks first. A single commit changes metab's error paths. **This is not in the user's parity list, so it is a decision for the user:** align to lipid, or keep a per-omic flag.
- **R3 Sample-column detection.** Each omic has two detectors (builder `getLipidDesignSampleColumns`: name patterns, numeric only without a map; validator `lipidDesignSampleColumnsForAssay`: numeric + patterns), and the lipid and metab pattern lists differ. KIT-102's text-numeric conversion makes more columns numeric. Before unifying, check that every import sets `column_mapping$sample_columns`, or keep both detectors' semantics.
- **R4 User-visible strings.** These are tested and waited on, so they must be reproduced exactly:
  - the validator's label ("Lipidomics design …" / "Metabolomics design …");
  - "Design matrix and contrasts saved successfully!" (MCI-027, journeys);
  - "No samples have been assigned to groups." (prot adds a sentence);
  - the `tech_rep_summary` format, which is identical in all three and waited on by the journeys.
- **R5 Browser contract:**
  - module ids: `design` + `builder`; prot `design_matrix` + `builder`;
  - the 38 ids and the `main_tabs` values ("Factors", "Assign Metadata", "Technical Replicates", "Contrasts");
  - test ids: `prot-design-*`, `lipid-design-import-*`, `metab-design-import-*`, `<omic>-tab-design`;
  - the step-map label `module("lipid_design")` for trx (`tools/profiling/workflow_kit.R:23`, currently modified in the working tree by KIT-098).
- **R6 Public API.** The exported `mod_{lipid,metab,prot}_design_{ui,builder_ui,builder_server}`, `mod_lipid_design_server`, `registerMetabDesignPreviewOutputs` and `registerProtDesignServerShells` stay as thin wrappers. `func_general_applets.R:268-276` runs `mod_prot_design_builder_server` standalone with plain reactives and no owner.
- **R7 Memory (KIT-075/078/082).** Builder tables are held by reference. A shared builder must not cache tables in reactives, or the measured app floors regress. Prot's DIA references (`newDIASavedReactiveVal`, `getDIAReactiveReference`) need the adapter.
- **R8 Silent skips.** Renamed internals turn the 42 guarded skip sites (lipid-13a 15, metab-04 11, prot-04a 16) into skips, not failures. Compare against KIT-101's skip baseline.
- **R9 Proteomics fit.** Prot shares the UI and the design-matrix algorithms, but not the data model or the commit (per-workflow-type objects, UniProt post-step, DIA reclamation, `needs_numeric` conversion at design). Whether prot joins the builder (with the `dia_long` adapter) or keeps its own is KIT-101's call; the line estimates show both.
- **R10 Small latent differences**, recorded and not fixed:
  - builder and import friendly names differ for group names containing `.`;
  - the existing-design initial state collects `factor1` and `factor2` levels, not `factor3`;
  - prot's dead `_minus_` gsub;
  - `buildLipidDesignContrastState` assumes the `group` prefix.
- **R11 Interim growth.** KIT-109 owns removing "the profile hooks and the duplicate copies". If KIT-103 only adds the shared module, the line count rises by about 2,500 until KIT-109. Recommendation: KIT-103 switches lipid, metab and trx and deletes the copies left with no callers (metab builder server and validator, lipid helpers), quarantining their seam tests in the same ticket; KIT-109 removes the remaining hooks.
- **R12 Sequencing.** KIT-098 has uncommitted edits to `tools/profiling/workflow_kit*.R` and `tests/testthat/test-workflow-kit-harness.R`. KIT-103 starts after those land.
