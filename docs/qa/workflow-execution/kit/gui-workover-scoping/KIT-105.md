## 3. The shared frame and the plugin interface

### 3.1 The frame (one module for every omic's normalisation tab)

One module, `mod_omics_norm_ui(id, config)` and `mod_omics_norm_server(id, workflow_data, experiment_paths, omic_type, experiment_label, selected_tab, config)`. KIT-101 or KIT-102 fixes the file name; `R/mod_omics_norm.R` is proposed.

The current public functions stay as wrappers so that the e2e helpers, the harness step map and `NAMESPACE` do not change:
- `mod_lipid_norm_ui` and `mod_lipid_norm_server`;
- `mod_metab_norm_ui` and `mod_metab_norm_server`.

The frame provides:
1. **Option panel host.** Column 3 holds `config$norm_options`. That is either a vector of shared section names or a function `(ns)` for a bespoke panel. The shared sections are:
   - `aesthetics`;
   - `itsd`;
   - `log2`;
   - `between_sample`;
   - `ruv_iii` (noun, default k and help text from the configuration);
   - `actions` (run and reset buttons);
   - `export`.
2. **QC tab registry.** Column 9 is the `norm_qc_tabs` tabset. Its tabs are `itsd`, `ruv`, `pca`, `density`, `rle`, `correlation`, `correlation_filter` and `log` (today's `buildLipidNormQcTabsetPanel`), filtered by `config$norm_tabs`.
3. **Stage grid.** Figure tabs are generated as `<kind>_<post_filter|post_norm|ruv_corrected>_assay<n>`, with `assay<n>_label_<kind>` labels, for `config$norm_assay_slots` rows. The output ids are fixed, because the e2e lanes and tests read them. Each stage's file prefix and caption come from the configuration.
4. **Server wiring.** The frame registers those observers and outputs once. Run, reset, correlation apply/skip and export call the plugin (3.2).
5. **Completion.** The frame logs, raises `plot_refresh_trigger` and sends the notification. The plugin's `finish` adds what is omic-specific, such as trx's `tab_status$normalization`.

### 3.4 Proteomics: fits the option sections, not the figure frame

The proteomics figure frame differs in five ways:
- **Output ids.** They are `pca_post_filtering`, `pca_post_normalization` and `pca_ruv_corrected`, with no assay suffix.
- **Image sources.** Images come from recorded paths (`normData$qc_plot_paths`), regenerated when the aesthetics change. They are not found by file-name convention.
- **Extra tab.** It has a "Post-Normalisation QC" filtering-summary tab and a DIA_LIMPA RUV-covariates panel.
- **Different button.** The export button is `export_filtered_session`, plus the `export_s4_compatibility` download.
- **No Log tab.**

Its run is one saved operation (`diaNormalizationOperation`) on the DIA owner. It runs in process and not on the omics runner.

Its QC products are computed from the S4 inside `mod_prot_norm_qc_generation_helpers.R` (403 lines). That is core work in a module file. Moving it is a relocation that changes nothing, but it touches proteomics oracles and lanes.

**Recommendation:** in KIT-105, proteomics takes only the shared `ruv_iii` and `aesthetics` option sections, and only if KIT-101's entry-point suite covers `mod_prot_norm_server` on DIA, LFQ/TMT and DIA_LIMPA. Its figure frame, run and QC-product relocation stay out (D3).

### 4.2 The proof

1. **Test first.** Take the normalisation slice of KIT-101's entry-point suite for lipid, metab and trx, run both in process and on the managed fixture of `helper-workflow-omics-worker.R`, and freeze it on today's code. It should capture:

   - the outputs: the 24 image `src`/`alt` values, labels, log lines, `ruv_qc_ui`, the correlation summary and `final_qc_plot`;
   - notifications and `tab_status`.
2. **An id inventory.** The rendered norm UI of lipid, metab and trx has the same input ids, output ids, `data-testid` values and tab titles (for example "Correlation Filtering"). 3. **Journeys.** Lipid and metab screen journeys are exact against their v1.7 oracles. Trx journeys are exact against KIT-098's (protocol v1.8). Proteomics journeys apply only if D3 brings it in.
4. **e2e lanes.** `test-e2e-lipidomics-canonical.R`, `test-e2e-metabolomics-lc-gc.R` and `test-e2e-trx-journey.R` must pass, plus the prot lanes if D3 applies.
5. **Quarantine manifest.** It lists every quarantined test with the internal that replaced it. The skip count is compared with KIT-101's baseline. The two silent-skip sites (lipid-12's file guard, 03b's symbol loader) are quarantined explicitly, so the count cannot rise unnoticed.

KIT-105 owns none of the four parity decisions: text-numeric is KIT-102, finalise is KIT-104, tree-cut is KIT-106, vendor formats are KIT-102. The scientific contract is therefore "no change": every committed state, file and figure stays identical.

## 5. Risks, and lines before and after

### Risks

- **R1. Hidden twin differences.** Each of these must be settled by the entry-point suite on today's code, not chosen in review:
  - skip-correlation sets `normData` flags before the store commit in lipid and after it in metab, which matters only when the commit fails;
  - the final-PCA error catch site differs;
  - metab's composite returns extra fields;
  - the export summary text has not yet been compared byte for byte.
- **R2. Session-RDS contents are a compatibility contract.** The `feature_counts` sample rule and the counts field differ per omic, so both are kept as configuration and not unified silently.
- **R3. The in-process ITSD selection differs between paths.** In process, it rebuilds the selection tables from the whole S4. When managed, it uses `itsd_candidate_ids`. Using the ids in both paths would be a behaviour change, so the in-process resolution is kept.
- **R4. The managed-path evidence must be re-pointed.** The KIT-078/082 worker tests name lipid/metab observer internals. A careless quarantine would drop that evidence.
- **R5. The id contract must hold.** The input/output ids, test ids and tab titles are read by the e2e lanes and harness. The public module names appear as strings in the frozen harness step map, so `mod_lipid_norm_*` and `mod_metab_norm_*` are kept as wrappers. The harness changed during this scoping (`c783e97a`, KIT-098 trx route); the step map is re-read at authoring.
- **R6. Trx's mount and coordination.** Trx is mounted through `mod_lipid_norm_*(profile =)`, and `mod_transcriptomics.R` belongs to KIT-102's shell. Moving trx onto the frame needs either KIT-102's shared mount or a one-line mount change, with KIT-109 removing the hooks.
- **R7. Size.** About 6,770 GUI lines and about 14,000 test lines are touched. The stub's 8 h estimate is low. Suggested order inside the ticket, with the entry-point suite run after each step:
  1. move the core pieces and re-point the bindings;
  2. build the frame with lipid on it;
  3. put metab on it;
  4. put trx on it;
  5. delete the replaced files and quarantine their tests.
- **R8. Convention divergences, recorded and not fixed.** The existing snake_case public module names, the `fluidRow`/`wellPanel` layout, and the managed runner instead of `ExtendedTask` are compatibility contracts. Changing them would break the e2e lanes and the harness.
