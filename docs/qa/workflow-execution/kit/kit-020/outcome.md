- The import's owned path (`applyProtImportResultToWorkflow`, the import observer's `deferFasta`) covers every owned format: the table is owned by the store, the import metadata recorded (`recordDIAImportMetadata` works on the protein-level readers' long tables: `Run`, `Intensity`/`Abundance`), the FASTA processed after the table is released. The roles `<format>_report`/`fasta` were already recorded for every format (verified).

- The two `protein_s4_initial` probes in `mod_prot_qc.R` read the state reference on an owner instead of hydrating.
- Replay accepts the four report roles (ticket item 6: the design precondition was already generic, `utils_workflow_analysis_record.R:439-444`; only the role list changed).
- Audit repairs (2026-10-20, [AUDIT-20261020.md](AUDIT-20261020.md), [REMEDIATION-20261020.md](REMEDIATION-20261020.md)): the manifest's type comes from the store identity (not the manager's field, which is the fresh default `LFQ` until an import sets it), `openDIANativeSession` requires the manifest's type to equal the store's and sets the reopened owner's type from the store identity (F-07; an export-time refusal was tried first and withdrawn because fresh adapters in the GUI lifetime tests export before any import sets their type); an owner the import attached accepts only its own format (F-09); a Spectronaut peptide export (`quantity_type = "pep"`) never attaches (F-11); the roxygen blocks are separated (F-13).
