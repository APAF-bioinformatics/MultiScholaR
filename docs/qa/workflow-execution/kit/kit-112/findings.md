## Lead decisions at W1 (2026-11-10)

- **`112f` is bound** (D8's failure half), because P3 found an honest input. It is `101l` on `kit_112` with `driver_settings = list(da = list(formula = "~ 0 + group + Run"))`. The controller's validation accepts this formula and the kernel refuses it in process ("No finite residual standard deviations", a saturated model). The expectation is `journey_failed` at `da`, with the `DA-contrast-output` dispatch at 1 request and 0 complete, and the store head the pre-DA state (`111l`'s head before `da`). The coordinator applies `case$driver_settings` over the journey (`workflow_kit_coordinator.R:323`); the fixture corpus overrides only normalisation.
- **The request half stays free of further reads.** W1's `request-half-hydration.md` found that it reads only state records, the design table and zero-row schemas. The design-only read has a transient heap peak of about 0.15 GiB that does not grow with the data. W2 adds no read there.
