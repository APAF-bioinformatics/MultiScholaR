# PQC-003: Count distinct peptide and replicate identities

## Description

The sample and replicate filters currently risk treating duplicated rows as
additional evidence. Define both filters in terms of explicit identities and a
validated experimental design so repeated precursor or annotation rows cannot
inflate peptide or replicate support.

## Scientific Contract

- Per-sample evidence is the number of distinct `(Protein.Group,
  Stripped.Sequence)` identities observed in each `Run` after rollup.
- Replicate support is the number of distinct observed `Run` values for each
  `(technical-replicate group, Protein.Group, Stripped.Sequence)` identity.
- The design has exactly one row per run and every quantitative run maps to one
  design row; duplicates and unmatched IDs fail before filtering.
- The packaged default sample minimum is 500, matching the existing GUI
  intention, while an explicit user/config override remains authoritative.
- A peptide supported in any biological group remains globally retained, and
  observed singleton values in other groups remain present; support must still
  be reported separately for every group.

## File-by-File Plan

- Replace incidental `n()`/row-count decisions with `n_distinct()` over the
  declared identities.
- Complete support tables against the validated design so absent observations
  are represented as zero rather than disappearing from denominators.
- Resolve one canonical sample threshold through config, S4 method, module UI,
  execution, and audit metadata.
- Make the current “supported in any group” policy explicit in helper names,
  result text, and saved configuration.
- Add direct helper and module tests with duplicated rows, shared sequences,
  unequal groups, inclusion lists, and broken design mappings.
