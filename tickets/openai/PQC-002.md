# PQC-002: Replace percentage-derived peptide missingness with direct counts

## Description

The GUI asks for a minimum number of observed replicates and passing groups, but
the implementation converts these values to shared percentages. A single
percentage cannot represent the same minimum count across unequal group sizes.
Implement the displayed rule directly.

## Scientific Contract

- An observation is finite and at or above the resolved intensity threshold.
- Count distinct run IDs, not rows, per `(Protein.Group, Stripped.Sequence,
  biological group)`.
- A group passes when observed runs are `>= min_reps_per_group`.
- A peptide passes when passing groups are `>= min_groups`.
- Strict mode requires every design run to have an observed value.
- Use the S4 object's normalised peptide quantity for the default cross-sample
  percentile threshold; retain an explicit quantity-column override.

## File-by-File Plan

- Replace percentage-derived decisions in the peptide helper with direct count
  tables completed against the validated design.
- Stop using `updateMissingValueParameters()` for the peptide GUI decision;
  leave it untouched for other workflows unless separately tested.
- Preserve legacy percentage arguments as deprecated explicit API inputs, with a
  deterministic adapter and warning; new GUI/config paths use counts.
- Save the numeric intensity threshold, source quantity column, per-group
  support, and exact failure reason in audit metadata.
- Add unequal-group and duplicate-run fixtures.

## Evidence

- Focused ticket command: 154 passing assertions, zero failures, warnings, or
  skips. Config parsing and peptide module-CI add 83 passing assertions with
  zero failures/warnings.
- The direct fixture has biological groups of 2, 3, and 6 runs. With
  `min_reps_per_group = 2`, every support-table row records exactly two required
  distinct runs; the six-run group cannot pass with a smaller absolute count.
- A feature observed at intensity exactly `15` in exactly two runs of each group
  passes a threshold of `15` and `min_groups = 3`, proving all three inclusive
  `>=` boundaries.
- Strict mode replaces each group requirement with its complete design-run
  count and retains only the fully observed feature. NA, NaN, and Inf are not
  observations and are counted in the audit summary.
- Duplicate `(protein, peptide, run)` rows, duplicate design run mappings,
  unmapped input runs, and globally absent design runs all fail with bounded
  offending IDs before support is calculated.
- The S4 method records `Precursor.Normalised` as its default threshold source;
  an explicit `Precursor.Quantity` override produces and records the independent
  raw threshold.
- The GUI preview states the exact distinct-run and passing-group counts, sends
  those same values explicitly to the method, and saves the executed support
  summary. It no longer calls `updateMissingValueParameters()`.
- Percentage-only direct calls and saved object configs remain callable through
  the algebraically exact old-rule adapter and emit a deprecation warning.
  New packaged config fields are parsed into numeric/logical values and exercise
  the direct path without warning.
- The count implementation is deterministic and in-process. A supplied
  multidplyr cluster emits explicit migration guidance and returns an identical
  result; no pseudo-parallel branch remains.
- Protein-level percentage helpers were not modified. Existing equal-size
  peptide compatibility fixtures and the broader peptide module-CI suite remain
  green.
- Independent rollback baseline: `a2ecddc` (`fix: count distinct protein
  identification evidence`). Reverting PQC-002 files to that revision restores
  percentage-derived decisions, raw-default thresholding, and the unequal-group
  minimum-replicate defect.
