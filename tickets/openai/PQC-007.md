# PQC-007: Carry Protein.Group through protein quantification

## Description

The DIA-NN active protein identity is `Protein.Group`, but peptide-matrix and IQ
handoff code currently renames or hardcodes it as `Protein.Ids`. Carry the
declared active key end to end so protein groups cannot be split, merged, or
mislabelled during normalisation, imputation, IQ rollup, or S4 construction.
Keep `Protein.Ids` beside it as accession provenance.

## Scientific Contract

- `peptideS4@protein_id_column` declares the active protein key; for DIA-NN it is
  `Protein.Group`.
- Matrix row keys have a reversible, collision-checked map back to
  `(Protein.Group, Stripped.Sequence)`; display strings are not parsed as the
  sole source of identity.
- IQ receives the active protein column as `primary_id` and the stripped peptide
  as `secondary_id`.
- IQ output parsing, surviving-sample detection, protein-object construction,
  counts, saved configuration, and result text all use the dynamic active key.
- `Protein.Ids` remains annotation/provenance and never substitutes for the
  active DIA-NN group key.
- The approved IQ compatibility behavior remains unchanged: synthetic
  compatibility q-values, remaining missing IQ inputs converted to zero, and
  `normalization = "none"`.

## File-by-File Plan

- Stop renaming the active key to `Protein.Ids` in `calcPeptideMatrix()` and add
  a reversible feature-key table that survives matrix transformations.
- Preserve protein-key metadata through peptide normalisation, missingness,
  accession, and imputation round trips.
- Parameterise the IQ input, output restoration, sample-column discovery,
  `ProteinQuantitativeData` construction, audit config, and protein counts from
  `peptideS4@protein_id_column`.
- Retain an accession provenance table relating `Protein.Group` to
  `Protein.Ids`, including many-to-many groups without silently choosing one.
- Update only the DIA peptide-to-protein workbook seam and add deliberate
  `Protein.Group != Protein.Ids` fixtures.
