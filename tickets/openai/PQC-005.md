# PQC-005: Harden precursor-to-peptide rollup integrity

## Description

Retain the intended quantitative rule: charge states, unmodified peptides, and
modified peptidoforms are summed into a single stripped-peptide quantity for
protein quantification. Add the data-shape, missingness, and scale safeguards
needed to make that sum valid and auditable.

## Scientific Contract

- Aggregation key before rollup is the declared run, active `Protein.Group`, and
  precursor identity.
- Output identity is `(Run, Protein.Group, Stripped.Sequence)`.
- Exact duplicate precursor identities cannot be silently double-counted.
- Quantities are linear, finite/non-negative where observed, and never log-summed.
- If at least one component is observed, sum observed components; if all
  components are missing, retain `NA` rather than manufacturing zero.
- Identification peptide/peptidoform counts remain frozen and are not recomputed
  from rolled-up rows.

## File-by-File Plan

- Add preflight uniqueness and scale assertions with bounded examples in errors.
- Implement an all-missing-preserving sum helper shared by sequential and
  multidplyr paths.
- Prove sequential/parallel equivalence.
- Preserve `Protein.Ids` accession provenance beside active `Protein.Group`.
- Record counts of precursor rows, unique precursor identities, stripped peptide
  identities, partial-missing sums, and all-missing outputs.
- Update method documentation and rollup module output.

## Evidence

- Focused ticket command: 88 passing assertions, zero failures/warnings, and one
  unrelated Git LFS snapshot skip.
- The six-row synthetic fixture contains one unmodified and two modified forms,
  each at charge 2 and 3. Raw values `1 + 2 + 4 + 8 + 16 + 32` produce exactly
  `63`; normalised values produce exactly `126`; the output has one stripped
  peptide and three quantitative peptidoforms.
- Duplicate declared precursor identities fail with bounded
  `(Run, Protein.Group, Precursor.Id)` key examples. Negative, infinite, NaN,
  and explicitly logged inputs fail with linear-scale migration guidance.
- Partial missing raw components return the observed sum, while an all-missing
  normalised component set remains `NA`. The module saves and displays both
  missingness counts and the declared aggregation rule.
- A real two-worker `multidplyr` fixture is identical to the sequential result
  after deterministic sorting.
- Real-data rollup after the accepted `>=1 peptide / >=2 peptidoforms` gate:
  cotton has 507 biological protein groups, 12,099 accepted precursor rows, and
  11,766 output stripped-peptide/run identities; KV has 1,763 groups, 157,893
  accepted precursor rows, and 130,036 output identities. Both datasets pass
  precursor-identity and linear-scale validation and have zero partial/all-
  missing raw or normalised outputs.
- `Protein.Group` remains the active quantitative key, `Protein.Ids` is reduced
  only as accession provenance, and frozen identification counts are joined
  back without recomputation.
- LFQ/TMT-specific code was not modified by this ticket; the existing legacy
  direct helper fixture remains in the focused regression suite.
- Independent rollback baseline: `a2ecddc` (`fix: count distinct protein
  identification evidence`). Reverting the PQC-005 changes to that revision
  restores the prior unguarded two-pass sums, duplicate inflation risk, and
  ambiguous missing/log-scale behavior.
