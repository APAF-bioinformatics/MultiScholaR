# PQC-001: Lock DIA-NN q-value and threshold contracts

## Description

Replace ambiguous confidence plumbing with one explicit DIA-NN contract. The
identification population must be filtered at `0.01` using the correct precursor
and protein-group fields before evidence identities are counted.

This ticket also closes the missed regression in the protein-evidence filter:
the GUI/config aliases `peptides_per_protein_cutoff` and
`peptidoforms_per_protein_cutoff` must resolve to the same executed values as
the canonical `num_*_thresh` arguments. The test must exercise the config-only
path, not merely the GUI's new explicit forwarding.

## Scientific Contract

- Current DIA-NN main reports use `Q.Value <= 0.01`,
  `Global.Q.Value <= 0.01`, and `Global.PG.Q.Value <= 0.01`.
- `Proteotypic == 1` remains required for this workflow.
- `PG.Q.Value` must never be copied into `Global.Q.Value`.
- Inputs without a required confidence metric enter only through an explicitly
  named legacy/upstream-prefiltered mode with recorded provenance; no silent
  substitution or fabricated claim of q-validity is allowed.
- The executed protein evidence threshold defaults to `1 peptide / 2
  peptidoforms`, and any user override must be honoured exactly.

## File-by-File Plan

- Amend the q helper and S4 wrapper to resolve distinct column roles and produce
  an actionable schema error.
- Make the GUI's fixed `0.01` thresholds read-only text or disabled controls and
  correct the `Global.Q.Value` label to “global precursor q-value.”
- Persist all applied metric names and values in object args/state configuration.
- Keep both historical and canonical protein-evidence parameter names as aliases
  but record only the canonical resolved values.
- Add focused unit/module tests for actual filtering and all parameter routes.
