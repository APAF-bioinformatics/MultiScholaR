# PQC-006: Classify and exclude decoys and contaminants auditably

## Description

DIA-NN decoys and FASTA contaminants have different semantics. Standard main
reports generally omit decoy identifications unless `--report-decoys` is used.
Contaminant FASTA entries, including cRAP, are target sequences and can remain in
the report unless deliberately tagged/filtered. MultiScholaR must make that
distinction explicit and reproducible.

## Scientific Contract

- Apply q-value filters before any downstream operation, then classify/exclude
  non-biological targets before frozen biological identification evidence.
- Exclude `Decoy == 1` whenever the column exists.
- Classify contaminants only from explicit columns/tags, token-wise accession
  matching against a versioned manifest, or a supplied user manifest.
- Never classify by an unconstrained description substring or organism guess.
- Preserve all rows in the immutable import state and write the exact exclusion
  reason/source for every removed analysis row.
- Report both “all q-valid targets” and “biological targets after exclusion.”

## File-by-File Plan

- Add a pure classification helper returning `is_decoy`, `is_contaminant`,
  `exclusion_reason`, and `classification_source`.
- Add a versioned cRAP accession resource only after verifying its source,
  licensing, version, and checksum; otherwise require a user manifest and leave
  the packaged-manifest criterion unfulfilled.
- Integrate the classifier between the confidence gate and identification
  evidence annotation.
- Add GUI/state summaries and downloadable exclusion ledgers.
- Add fixtures with semicolon-delimited mixed groups and explicit precedence
  rules; never partially relabel a group without a recorded group-level policy.
