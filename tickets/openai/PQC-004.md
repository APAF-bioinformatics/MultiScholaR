# PQC-004: Correct technical-replicate imputation

## Description

Retain technical-replicate mean imputation, but make its eligibility and
provenance scientifically exact. Equal-valued measurements must still count as
different observed runs, duplicate rows must not count as extra replicates, and
sample-name regexes must not silently remove legitimate data.

## Scientific Contract

- A technical-replicate group is supplied explicitly by design metadata and
  contains at least two distinct design runs.
- Availability counts distinct run IDs, never distinct quantity values or rows.
- The imputation mean uses every observed measurement in the same declared
  technical-replicate group for the same peptide identity.
- A group is eligible when its missing fraction is `<=` the configured maximum;
  therefore exactly 50% missing passes a 50% maximum.
- An all-missing group is never imputed and duplicate run-feature observations
  fail before the mean is calculated.
- Raw peptide quantity remains the intended IQ imputation scale, and every
  generated value is marked `is_imputed = TRUE` without changing observed rows.

## File-by-File Plan

- Replace distinct-value and row counts with distinct-run availability and a
  validated run-feature table.
- Calculate the mean over all observed run measurements within each declared
  technical group and preserve observed/imputed provenance on output.
- Remove the default `HEK` regex exclusion. Add an explicit design flag or
  configured exclusion field; retain `hek_string` only as an opt-in deprecated
  compatibility argument with a warning.
- Remove whole-table console output and replace it with bounded audit summaries.
- Expose the exact eligibility denominator, maximum-missing boundary, quantity
  column, and explicit exclusion source in module state/audit output.

## Acceptance Criteria

- [x] Equal-valued measurements in different runs count as separate observed replicates.
- [x] Duplicate run-feature rows fail rather than biasing counts or means.
- [x] Exactly 50% missing is eligible when the configured maximum is 50%.
- [x] All-missing groups and single-run groups are never imputed.
- [x] Only observations in the same explicit technical-replicate group contribute to a mean.
- [x] Observed values remain unchanged and imputed values carry an unambiguous `is_imputed` flag.
- [x] No sample is excluded merely because its name matches `HEK`, and no full table is printed during execution.

## Implementation Evidence

- The exact focused method/module suite passed 170 assertions with no failures,
  test warnings, or skips. Config and module-CI compatibility added another 84
  passing assertions.
- The 20-row boundary fixture contains 11 observed raw measurements. Four
  eligible missing rows are imputed and flagged, while five remain missing by
  design (all-missing, over-boundary, or explicitly excluded). All observed raw
  and imputed-output values remain unchanged.
- Two equal-valued observations in distinct B-group runs produce
  `observed_distinct_runs = 2` and a mean of 5. An A-group feature at exactly
  `1 / 2` missing is eligible; a B-group feature at `2 / 3` missing is not.
- A B-group missing value uses only B-group values (10 and 20, mean 15), even
  though the same feature has A-group values of 100. All-missing and single-run
  groups never generate an imputation.
- Duplicate `(Run, Protein.Group, Stripped.Sequence)` rows, duplicate design
  run IDs, and unmapped quantitative run IDs fail with the offending identity.
- `HEK_subject_1` participates normally by default. The explicit design flag
  excludes `QC1`/`QC2`; explicit legacy `hek_string = "HEK"` deterministically
  opts into regex exclusion and emits a deprecation warning.
- The helper produces no console table. Its bounded support table and summary
  record the distinct-design-run denominator, inclusive `<=` operator, raw
  quantity column, explicit exclusion source, observed/imputed counts, and skip
  reason. The S4 object and GUI saved state retain that metadata.
- Config-only and explicit S4 thresholds were exercised separately. The S4
  method uses `Precursor.Quantity`, preserving the approved raw-scale IQ handoff.
- The parsed `proteinMissingValueImputation` and
  `peptideMissingValueImputationLimpa` implementations are unchanged from
  baseline `a2ecddc`; the limpa characterization suite passed 22 assertions.

## Rollback Procedure

Revert only the PQC-004 hunks (or its eventual isolated commit) in the helper,
generic, module, config, documentation, and tests. Do not restore the whole
`R/func_peptide_qc_imputation.R` file because that would overwrite a pre-existing
user change after the peptide methods. Rolling back these hunks deliberately
restores distinct-intensity counting, the strict `<` boundary, the implicit
`HEK` exclusion, whole-table printing, and the absence of imputation audit
metadata.
