# Transcriptomics function-to-architecture runbook

Scope: map the functions in [transcriptomics_workflow.rmd](transcriptomics_workflow.rmd) to the existing performance architecture. This is an implementation guide, not an implementation or a claim of measured transcriptomics gains. GUI controls, reactive wiring, navigation and GUI rollout are outside scope.

The transferable P14 idea is to keep large tables on disk, execute suitable work in bulk, pass only required data into R, and save accepted outputs without collecting another full copy. It is not an automatic converter for arbitrary R functions. For this workflow, statistical fitting remains in R initially; the surrounding reads, selections, joins, output handling and object lifetimes are the first adaptation targets.

**fastduckdb is part of the proposed data path**, using its native query owner and Arrow transfer/writer facilities, not merely an extra package attached around DBI. `reader = "fastduckdb"` selects a reader; it does not automatically create that query owner. Also, `saveWorkflowTableQuery` currently uses DBI directly: do not send a native fastduckdb connection through it. Use the qualified query-to-writer lifecycle or introduce the smallest tested routing change when that consumer is implemented.

Retain eight DuckDB threads. The current bulk helper sets a 12 GiB engine budget and disables spill; the surrounding process guard remains necessary. Disabling incidental insertion ordering is a candidate only where explicit scientific and final output order are already enforced. A 10,000-row transfer limit does not limit memory in upstream sorting, joining or aggregation. DuckDB documents allocations outside its buffer manager and blocking-operator limits: [memory guidance](https://duckdb.org/docs/stable/guides/performance/how_to_tune_workloads.html).

## How to apply the mapping

```text
counts file + design + annotation + contrast
                  |
        validate identities and schema
                  |
       durable counts + ordered axes
                  |
       admitted R statistical method
       (edgeR / CCA / RUVs / RUVIII)
                  |
       accepted products + provenance
             /              \
  fastduckdb selections,      bounded render inputs
  annotation joins, exports  and native diagnostics
             \              /
        durable outputs and references
```

1. **Extract one chunk's computation with explicit parameters.** Inputs are table/product references, ordered design and scalar options. Resolve source IDs and effective defaults before execution. Keep paths, live connections and callbacks out of saved scientific metadata. Preserve the notebook algorithm before changing its execution.
2. **Choose a physical count layout deliberately.** Wide gene rows suit complete-gene matrix assembly. More than 63 sample columns plus GeneID exceeds a single `streamSavedWorkflowTable` request, but `streamWorkflowTableRows` already combines bounded column reads. Reuse it first, checking complete row identity before placing each batch into one preallocated, admitted matrix; never retain a list of full-matrix fragments. Existing consumers are `streamWorkflowTableRows` call sites in [utils_workflow_dia_state.R](../../../R/utils_workflow_dia_state.R) and [utils_workflow_dia_qc_rollup.R](../../../R/utils_workflow_dia_qc_rollup.R). Its wide path uses fixed 10,000-row reads and checks 64 MiB only after assembly; it does not adapt batch size to width. Preflight the complete batch footprint, including strings and temporary copies. If that cannot fit, refuse the current route and qualify a narrowly scoped byte-aware batching adaptation before use. This matters especially for the sample-by-gene RUVIII export. A long GeneID/Run/count table avoids width limits but expands rows and may require an expensive pivot. Measure that choice instead of assuming long format wins; do not raise common limits.
3. **Budget the R calculation honestly.** One double matrix alone uses approximately `8 * genes * samples` bytes, before dimnames, transposes, S4 objects, fits, decompositions and output copies. Estimate the live set for the particular method and measure the entire process group. If it cannot fit, refuse that route; disk input is not proof that the statistical kernel is out-of-core. Delayed containers are not a drop-in answer when a method coerces to a dense matrix.
4. **For relational work, reuse connection ownership and the staged writer.** Bind scalar values; quote trusted identifiers; bulk-load only admitted small lookup tables and bind larger saved tables as described below; preserve explicit output ordinals. Stream query output once, calculating small summaries during the same pass. Use fastduckdb query wrappers, not DBI calls on native handles. Finish and validate the staged output, then use the existing durable commit. On error/cancellation close result, scope and unfinished writer without deleting accepted input artifacts.
5. **For R work, minimize overlap rather than changing mathematics.** Run one statistical stage at a time. Save required products and remove obsolete references when safe, including references captured by plot objects and environments. Do not promise immediate RAM release from `rm()`/`gc()`. Retain any fit required by a declared downstream consumer; measure serialization and restoration costs too.
6. **Separate science from presentation.** Persist compact CCA curves, W, ordered result tables, PCA scores/variance and exact RLE statistics. Appearance changes should not rerun normalization or DE. A whole-object RDS remains whole-object materialization on read; use the table codec for large independently readable products.

### Initial ingestion: the missing producer boundary (TR-A02)

This is proposed adapter work, not an existing qualified importer. The narrow starting route is a bounded text parser feeding the existing staged table writer:

```text
source text + explicit schema + authoritative design
 -> bounded parsed rows, carrying original source ordinal
 -> encoded counts and annotation stages owned by saveWorkflowTable
 -> full-input validation + finished tables
 -> accepted descriptors, then normal saved-table readers
```

Resolve delimiter, header, encoding, missing-value policy, count types, GeneID/GeneName roles and sample columns explicitly. Generate source ordinals in parser order before any sorting; do not infer them from an unordered parallel query. A header/schema probe must not retain the full file. Parser batches need row and byte limits; use the same schema for every batch and reject malformed values rather than silently skipping or coercing them.

Within `saveWorkflowTable`'s `write_fn`, open the incremental writer with explicit restoration metadata, append each validated batch, and finish it. Use the existing schema-3 unknown-row-count mechanism when appropriate; derive the final count from the completed file. The producer must validate global GeneID uniqueness across batches, not just within each batch, and verify the complete sample-axis mapping. Use an owned staged scan or equivalent bounded validation; a growing R key set is not a bounded solution. No downstream computation may use partial counts or annotations. Keep both descriptors tied to the same input identity, and return the product set only after both tables and cross-table checks succeed; a file-level commit alone does not establish multi-product acceptance.

Abort unfinished writers and release owned parser/query resources on parsing, validation or publication failure. Leave original input bytes and previously accepted products untouched; staged validation files follow existing ownership/cleanup rules. A direct fastduckdb text scan is an alternative only after separately proving parsing, ordinal and codec equivalence; it is not required to unlock the first producer. The downstream relational path still uses fastduckdb. Neither a full `vroom()` followed by a chunked writer nor a full-table `as.data.frame()` demonstrates bounded ingestion.

### Large annotation and filter-mask routing (TR-A03)

Use `workflowQueryWriteLookup` only when both its native row limit (10,000) and estimated byte limit (64 MiB) pass. For a gene-scale annotation or keep-mask table, incrementally save rows keyed by GeneID using the same codec. Include the mask's source population identity and ordered selection semantics; validate one mask entry per expected gene and no unknown keys.

The proposed transcriptomics adapter must lease each saved input, validate ownership and descriptor identity, and bind trusted physical Parquet paths into its existing scoped fastduckdb query owner. That multi-input relation binding is adapter work to qualify, not a currently registered transcriptomics operation. Respect logical selections and codec storage/restoration rules; do not read the base Parquet directly when a reference denotes a filtered view. Join counts/results to those relations without collecting the annotation population into R. Check join cardinality and explicitly restore the source/result ordinal. Keep only admitted summaries and top-result projections in R.

Do not raise lookup limits, truncate genes, or repeatedly call `workflowQueryWriteLookup` with the same table name: it creates a table, not an append session. Required boundary cases are 9,999 / 10,000 / 10,001 rows and below/above the byte limit; also verify duplicate/missing keys, annotation text width, exact output order and cleanup.

For the native statistical contracts, consult the [edgeR guide](https://bioconductor.org/packages/release/bioc/vignettes/edgeR/inst/doc/edgeRUsersGuide.pdf), [RUVSeq vignette](https://bioconductor.org/packages/release/bioc/vignettes/RUVSeq/inst/doc/RUVSeq.html) and [ruv manual](https://cran.r-project.org/web/packages/ruv/ruv.pdf). Freeze the installed versions for each comparison; these online release documents can change. Neither the guide nor this map establishes that the current calls can run independently per arbitrary gene or sample batch.

## Scientific decisions and implementation traps to resolve first

- **Missing design (TR-A01):** when `design_matrix.tab` is absent, the notebook fabricates six RPMI and six Sera labels from column position and writes them to disk. Generalized extraction must require authoritative sample-to-group metadata and fail before statistics if it is unavailable. Preserve that fallback only as an explicitly bound workshop fixture whose sample identities/order have been verified independently. Test shuffled count columns with fixed Run-to-group metadata and missing-design input: labels must remain attached to Run IDs, and missing metadata must not create a plausible-looking design. This is a documented correctness change to agree when implementing, separate from execution-only parity; the notebook is unchanged here.
- **Replicates:** the notebook creates both RUVs groups and RUVIII M from `group`, while its RUVIII prose says technical replicate variation. Treatment membership alone does not establish technical replication. Confirm the study's experimental units and the intended within-group invariance assumption before operationalizing this path. Do not silently substitute the `Replicate` column or relabel biological replicates as technical ones.
- **Controls and tuning:** least-significant genes from the same dataset are inferred controls, not experimentally certified negative controls. Preserve that provenance and assess the model choice separately from storage parity. Guard too-few features (`max(10, ...)` can exceed the available genes), no successful grid members, malformed curves, insufficient rank and confounded W/design. These are preflight cases, not reasons to silently choose another K.
- **Existing RUV helpers differ:** [func_prot_norm_optimization_helpers.R](../../../R/func_prot_norm_optimization_helpers.R) implements `findBestKElbow` using a near-maximum plateau and minimum-effect rule. The notebook's `find_best_k` selects the first exact maximum under a K cap. They are not interchangeable. The existing peptide/lipid/metabolite RUV methods are precedents to inspect, not proof of equivalent RNA-seq methods.
- **Counts and formula:** notebook rounding before `newSeqExpressionSet` must not become silent correction of invalid counts. Declare the accepted input policy. Validate sample matching, duplicate IDs, zero libraries, empty filters, contrast syntax and estimability before allocation. The current contrast parser uses only the first non-header line; multi-contrast support would be a behavior extension.
- **Three different expression products:** TMM logCPM, RUVs-derived visualization correction, and RUVIII corrected integration data must have distinct identities and labels. None replaces raw counts in the negative-binomial model. The notebook's “raw” diagnostic is logCPM of already filtered counts, not the unfiltered input.
- **Presentation is still science-sensitive:** preserve PCA geometry/variance, RLE statistics, GeneID alignment and FDR populations. A PCA sign flip can be mathematically equivalent; compare aligned scores/subspaces as well as figures, with a predeclared rule. Preserve exact ID/mask/order decisions; set numeric criteria before testing and never widen them after a failure.

## Smallest useful implementation sequence and verification

**Baseline and attribution first (TR-A05).** Before selecting any performance adaptation, freeze a small representative non-GUI reference run and profile its current computation and object lifetimes (`profvis` for R call attribution, with the existing process-level memory instrumentation). Inspect input parsing/copies, simultaneously live matrices and fits, RLE long-table retention, exact-quantile working state, output serialization and teardown. Separate profiling from timed comparisons. A small fixture establishes observability and correctness, not the memory scaling of a large assay; gather evidence at the target shape only under a separately bounded run allowance if needed.

The rows below are dependency/candidate mappings, not an instruction to implement every optimization in numerical order. After the baseline gate, choose one mechanism supported by measured cost. Freeze source/build bindings, input dimensions and widths, science criteria, minimum worthwhile peak-memory reduction and acceptable elapsed-time tradeoff before seeing candidate results. Memory is the primary criterion; eight engine threads remain fixed. If no candidate addresses a material measured cost, retain the native route. This document authorizes no benchmark campaign or additional run.

| Order | Bounded adaptation | Evidence required before retaining it |
|---|---|---|
| 1 | Extract/freeze and profile the current non-GUI computation and its input contracts | Small reproducible reference fixture, exact axes/design/contrast, identified scientific decisions above, observable completion/failure and measured cost supporting the selected adaptation. Record existing failures rather than turning them into expected success. |
| 2 | Count ingress, stored filter mask, annotation join and output streaming | Exact counts/IDs/types/order and exports; duplicate/missing-key failures; no full-table collection in the migrated data path; finish/abort/publication-failure tests. |
| 3 | Sequential statistical ownership and compact reusable products | Same filtering, controls, K, W-derived fitted effects, DE statistics/FDR and required artifacts. Evidence that discarded objects are not retained through containers or plots. |
| 4 | RLE summary path and reusable PCA/CCA render inputs | Original versus adapted plot statistics, limits, factors and identities on small edge cases; complete-operation peak and elapsed time including writes/rendering. |
| 5 | Only if profiling still identifies a worthwhile cost: blocked correction or alternative matrix kernel | A separate scientific equivalence contract, package/API support, and measured benefit. Do not carry P14's independent-sample batching into globally coupled RNA models. |

Use fixtures with known count/design correspondence, shuffled rows/columns, missing design, duplicated gene symbols, ties, all-zero/constant genes, invalid counts, rank failure and failed grid members. For ingestion, cover parse errors and duplicate GeneIDs across batch boundaries plus cleanup after partial writes. For table routing, cover the lookup boundaries above and 64/65-column inputs, exact row identities, and complete wide batches below/above the byte ceiling. Check that failure leaves original inputs and accepted references unchanged. Compare gene and sample identities exactly; compare every retained numeric product against the frozen reference under predeclared criteria, including threshold decisions. Test installed package behavior when extracting notebook code into the package.

Before any expensive comparison, declare input/build bindings, runtime and attempt budget, common resource guard and the adoption decision. Prove instrumentation records completion and failure with a small case. Measure complete elapsed time, combined peak memory, anonymous/file-cache memory, swap, disk I/O, staged bytes, spill attempts and cleanup. Include the native method, input loading, serialization, export and teardown. An OOM control is a failure, not a speedup denominator. Eight threads remain fixed for the engine; avoid concurrent matrix jobs that multiply the live working set.

Completion for each adaptation means preserved science and required outputs, clean lifecycle behavior and a measured memory or throughput benefit under the same workload and guard. P14's DIA result motivates these patterns; it does not qualify transcriptomics performance. No GUI work or automatic routing is authorized by this document.
